# Контракт формата протокола встречи (v1.0)

Этот файл — единственный источник правды о формате протокола. На него опираются промпт скила `meeting-protocol` (LLM генерирует документ) и конвертер в Word (разбирает документ). Если правила здесь и в SKILL.md расходятся, приоритет у этого файла. Любое изменение формата вносится сначала сюда, затем в SKILL.md и в конвертер.

## 1. Общие правила текста

- Кодировка UTF-8, перевод строки LF. Конвертер предварительно нормализует CRLF → LF и удаляет пробелы в конце строк.
- Документ начинается с первой строки ответа. Текста до H1 и после последнего раздела нет. Обёртки в ``` нет.
- Пустые строки служат только разделителями блоков. Конвертер их игнорирует, их количество на разбор не влияет.
- Любая непустая строка документа относится к одному из типов из раздела 3. Строка, не подходящая ни под один тип, считается ошибкой формата.
- Текст внутри элементов берётся буквально, без интерпретации inline-markdown. Символ `|` в тексте запрещён.

## 2. Грамматика (EBNF)

```
document      = title, metadata, discussion, decisions, tasks, risks, [ summary ] ;

title         = "# Протокол встречи: ", text ;

metadata      = "## Метаданные",
                "- Дата: ", ( date | "не указано" ),
                "- Время: ", ( time | "не указано" ),
                "- Место: ", ( text | "не указано" ),
                "- Участники: ", ( text | "не указано" ),
                "- Ведущий: ", ( text | "не указано" ) ;

discussion    = "## Обсуждение", ( empty | topic, { topic } ) ;
topic         = "### ", text, bullet, { bullet } ;

decisions     = "## Решения", ( empty | numbered, { numbered } ) ;
numbered      = N, ". ", text ;           (* N = 1, 2, 3 … строго подряд *)

tasks         = "## Задачи", ( empty | table_header, table_sep, row, { row } ) ;
table_header  = "| Задача | Ответственный | Срок |" ;
table_sep     = "| --- | --- | --- |" ;
row           = "| ", text, " | ", ( text | "не указан" ), " | ", ( date | "не указан" ), " |" ;

risks         = "## Риски и открытые вопросы", ( empty | bullet, { bullet } ) ;

summary       = "## Краткое резюме", ( empty | bullet, { bullet } ) ;   (* только сценарий routes/quick_summary.md, 3–5 пунктов *)

bullet        = "- ", text ;
empty         = "— не указано —" ;          (* U+2014, пробел, «не указано», пробел, U+2014 *)
date          = DD, ".", MM, ".", YYYY ;
time          = HH, ":", MM, [ "-", HH, ":", MM ] ;
text          = непустая строка без "|" и без перевода строки, без ведущих/хвостовых пробелов ;
```

Каждый нетерминал в кавычках занимает ровно одну строку документа.

## 3. Типы строк (регулярные выражения)

Проверка идёт сверху вниз. Используется первое совпадение (синтаксис Python `re`, строка целиком):

```
H1                   ^# Протокол встречи: (.+)$
H2                   ^## (Метаданные|Обсуждение|Решения|Задачи|Риски и открытые вопросы|Краткое резюме)$
H3                   ^### (.+)$
Метаданные           ^- (Дата|Время|Место|Участники|Ведущий): (.+)$
Пустой раздел        ^— не указано —$
Шапка таблицы        ^\| Задача \| Ответственный \| Срок \|$
Разделитель таблицы  ^\| --- \| --- \| --- \|$
Строка таблицы       ^\| ([^|]+) \| ([^|]+) \| ([^|]+) \|$
Нумерованный пункт   ^(\d+)\. (.+)$
Маркированный пункт  ^- (.+)$
```

Проверки значений:

```
Дата (метаданные)    ^(\d{2}\.\d{2}\.\d{4}|не указано)$
Время (метаданные)   ^(\d{2}:\d{2}(-\d{2}:\d{2})?|не указано)$
Срок (таблица)       ^(\d{2}\.\d{2}\.\d{4}|не указан)$
```

Строки метаданных проверяются только внутри `## Метаданные`. В остальных разделах строка `- Дата: …` — это обычный маркированный пункт.

## 4. Допустимое содержимое разделов

| Раздел | Допустимо | Пустой раздел |
| --- | --- | --- |
| `## Метаданные` | ровно 5 строк метаданных в порядке Дата, Время, Место, Участники, Ведущий | не бывает (значения — `не указано`) |
| `## Обсуждение` | блоки `### тема` + ≥1 маркированный пункт под каждым | `— не указано —` |
| `## Решения` | только нумерованные пункты, нумерация с 1 подряд | `— не указано —` |
| `## Задачи` | шапка + разделитель + ≥1 строка таблицы | `— не указано —` (без таблицы) |
| `## Риски и открытые вопросы` | только маркированные пункты | `— не указано —` |
| `## Краткое резюме` (опц.) | 3–5 маркированных пунктов | `— не указано —` |

## 5. Плейсхолдеры

| Контекст | Строка | Где проверяется |
| --- | --- | --- |
| Неизвестное значение метаданных | `не указано` | значение после `: ` |
| Неизвестное название встречи | `не указано` | текст после `# Протокол встречи: ` |
| Неизвестный ответственный | `не указан` | 2-я ячейка строки таблицы |
| Неизвестный срок | `не указан` | 3-я ячейка строки таблицы |
| Пустой раздел | `— не указано —` | единственная непустая строка раздела |

Род плейсхолдера различается намеренно («не указано» — значение, «не указан» — ответственный/срок). Конвертер сравнивает плейсхолдеры точным совпадением строки.

## 6. Алгоритм разбора (для конвертера)

1. Нормализовать переводы строк, убрать хвостовые пробелы, отбросить пустые строки.
2. Первая строка должна совпасть с H1. Если не совпала, ответ считается не протоколом (например, уточняющим вопросом LLM) и в Word не конвертируется.
3. Разбить документ по строкам H2. Последовательность H2 должна быть ровно `Метаданные, Обсуждение, Решения, Задачи, Риски и открытые вопросы` плюс опционально `Краткое резюме` в конце.
4. Каждый раздел разобрать по таблице из раздела 4. Любая строка неожиданного типа считается ошибкой.
5. При ошибке вернуть её с номером строки. Конвертер ничего не угадывает: вызывающая сторона может попросить LLM перегенерировать ответ, передав текст ошибки.

## 7. Граничные случаи

### 7.1. Ничего не известно, кроме темы

```
# Протокол встречи: Обсуждение бюджета на рекламу

## Метаданные

- Дата: не указано
- Время: не указано
- Место: не указано
- Участники: не указано
- Ведущий: не указано

## Обсуждение

### Бюджет на рекламу

- Обсуждалась необходимость увеличить бюджет на контекстную рекламу.

## Решения

— не указано —

## Задачи

— не указано —

## Риски и открытые вопросы

- Не принято решение по размеру бюджета.
```

### 7.2. Задача без ответственного и с размытым сроком

Заметка: «надо бы кому-то обновить прайс, где-то на следующей неделе».

```
## Задачи

| Задача | Ответственный | Срок |
| --- | --- | --- |
| Обновить прайс-лист | не указан | не указан |

## Риски и открытые вопросы

- Не назначен ответственный: обновить прайс-лист.
- Срок задачи «Обновить прайс-лист» указан размыто: «на следующей неделе».
```

### 7.3. Противоречие в сроках

Заметка: «демо клиенту 20.03… (позже) нет, клиент попросил 25.03, фиксируем».

```
## Решения

1. Провести демо для клиента 25.03.2026.

## Риски и открытые вопросы

- В заметках два срока демо: «20.03» и «25.03»; принят более поздний и явный — 25.03.2026.
```

### 7.4. Несколько ответственных и символ «|» в исходном тексте

Заметка: «Петров и Сидорова — сравнить тарифы A|B до 01.04.2026».

```
| Сравнить тарифы A/B | Петров, Сидорова | 01.04.2026 |
```

### 7.5. Дата встречи без года, год неизвестен

```
- Дата: не указано
```

В рисках:

```
- Дата встречи указана без года: «14 октября».
```

### 7.6. Недопустимые варианты (ошибка формата)

```
## Задачи
- Обновить прайс (Иванов, до пятницы)        ← список вместо таблицы
| Задача | Ответственный | Срок | Статус |    ← 4 колонки
| Обновить прайс | TBD | скоро |             ← нестандартные плейсхолдеры, срок не дата
#### Детали                                  ← запрещённый уровень заголовка
**Итог:** ...                                ← inline-разметка и строка без типа
```
